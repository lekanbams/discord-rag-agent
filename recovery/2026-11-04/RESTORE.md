# Restore RAG-B v2

## Reuse existing Supabase

Keep the existing project and its v2 table. Fill its actual URL and backend service-role key in a private `.env`. Zeabur shutdown does not itself delete a separately hosted Supabase project. This package has not checked that project's current state.

If the expected table and function already exist, do not reset or delete them. Compare with `supabase-schema.sql` before applying any SQL.

## Create a fresh Supabase database

1. Review and run `supabase-schema.sql` in the new project's SQL Editor. It creates the v2 table, pgvector extension and restricted search RPC. It contains no document data.
2. Set the new project URL and service-role key privately.
3. Re-upload the original documents through the configured Telegram bot, or restore an exported set of v2 rows. Existing 768-dimensional vectors must be kept with their original embedding model metadata.
4. For a JSON export made by the included exporter, use an authenticated backend REST request to upsert `rows` in batches to `/rest/v1/ragb_documents_v2?on_conflict=chunk_key`, with `Prefer: resolution=merge-duplicates`. Exclude `id` from each row because it is generated by the destination. Review and test this import on an empty test project before production use. No importer was run or live restore tested for this package.

## Start the bot

From a checkout of the recorded v2 commit, or the included application-source ZIP:

```sh
cp env.example .env
chmod 600 .env
# Fill in the private values. Never commit .env.
python -m unittest discover -s tests -v
docker compose build
# Ensure the old production instance is stopped before starting this one.
docker compose up -d
docker compose logs --tail=100
```

The Compose configuration publishes no ports and mounts a named volume for chat memory. If using another deployment platform, reproduce its `/app/data` mount and UID 10001 write permissions.

An empty volume is supported. The application creates the SQLite schema automatically. `sqlite-schema.sql` is included as a reference, not an archive of old conversations.

## Discord and Telegram settings

- Enable Message Content Intent in Discord's Developer Portal.
- Grant the bot View Channels, Send Messages and Read Message History where needed.
- ADMIN_CHANNEL_ID must belong to DISCORD_GUILD_ID and be hidden from @everyone. Review all role/channel overrides separately.
- ADMIN_ROLE_ID must exist and be mentionable by the bot.
- Telegram uploads require approved numeric user IDs and a private chat.
- This version removes Telegram webhooks before polling. Ensure no other instance uses the same Telegram token.
- Uploads support PDF, DOCX, TXT, MD and CSV, up to 5 MB. Scanned PDFs require separate OCR.

## Verify before deleting the old deployment

Confirm Discord connection, one supported question, one follow-up, one unsupported question with a real private admin alert, and one successful Telegram document upload. Restart and verify memory persists if preserving chat history is required. Confirm answers omit public source lines. Compare document counts if restoring exported rows.

Local unit tests validate code behaviour only. They do not confirm credentials, live database schema, actual document rows, Discord permissions or successful migration.
